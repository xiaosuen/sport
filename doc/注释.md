# puppyfit-terminal 代码注释规范 (参考 AC_FS32)

> 本文档总结自 `AC_FS32` 项目中大量实际代码所采用的**结构化注释风格**。建议在 `puppyfit-terminal` 中逐步统一使用此规范。

## 1. 文件顶部模块注释（必须）

所有 Python 文件顶部应使用以下格式：

```python
'''
:brief 模块简要名称
:desc 详细描述，支持多行。
     第二行缩进对齐。
     可说明主要功能、技术选型、注意事项。

:author 作者名
:date 2026/03/28
:version 1.0.0
:history
    1.0.0 - 2026/03/28
        :brief Initial creation
    1.0.1 - 2026/03/29
        :brief 添加 xxx 功能
'''
```

**示例**（来自 AC_FS32）：

```python
'''
:brief MQTT 桥接客户端
:desc 后端与机器人终端之间的 MQTT 通信桥梁。
     订阅设备遥测、状态和事件主题，提供指令下发接口。
     基于 paho-mqtt v2，后台线程运行。

:author AC_FS32
:date 2026/03/19
:version 1.1.0
:history
    1.1.0 - 2026/03/22
        :brief 添加 TLS 支持 + 连续失败慢速重试(60s) + 日志降频
    1.0.0 - 2026/03/19
        :brief 初始版本
'''
```

## 2. 类/函数注释规范

### 类注释

```python
class MqttBridge:
    '''
    :brief 类简要说明
    :desc 更详细的描述，支持说明职责、关键特性。
    '''
```

### 函数/方法注释

```python
def publish(self, topic: str, payload: dict, qos: int = 1) -> bool:
    '''
    :brief 简要功能描述
    :desc 更详细说明（可选）
    :param topic: MQTT 主题
    :param payload: 消息负载（将序列化为 JSON）
    :param qos: 服务质量等级
    :return 是否发布成功
    '''
```

## 3. 关键标记一览

- `:brief` —— 必须，简要说明（一行）
- `:desc` —— 详细描述（支持多行）
- `:author` —— 作者
- `:date` —— 创建/修改日期（格式：`2026/03/28`）
- `:version` —— 版本号
- `:history` —— 版本历史（强烈推荐）
- `:param xxx` —— 参数说明
- `:return` —— 返回值说明

## 4. 其他推荐规范（同步 AC_FS32）

- 使用 `'''` 三引号包裹文档字符串
- 所有公开类和重要函数都应添加 `:brief`
- 历史记录采用**缩进列表**格式
- 日期统一使用 `YYYY/MM/DD` 格式
- 作者建议统一使用真实姓名或 `AC_FS32` / 项目代号

## 5. 与 puppyfit-terminal 现有风格结合建议

当前 `puppyfit-terminal` 中的文件多使用：

```python
"""
:brief ...
:desc ...
:author ...
:date ...
:version ...
:history
    - 1.0.0 ...
"""
```

建议**逐步统一**为 AC_FS32 的 `'''` + `:brief` 风格，以保持两个项目风格一致，便于后续代码复用和人员协同。
